# 邮件、3D 与资料库接入开发契约

日期：2026-09-08。用户要求先写好代码，资料实际录入与外部凭据接入留待后续。本轮不修改公网 DNS、不创建密钥、不导入客户资料、不调用付费模型、不发送外部邮件。

## 验收目标

- [x] 私有资料录入 API：文本及 PDF/DOCX/XLSX/CSV/TXT/Markdown 文件上传，原件私有保存，解析状态与明确错误，版本和人工启用/停用。
- [x] 解析与切块：页码/工作表/行号等出处，长度与文件限制；扫描 PDF 返回需要 OCR，解析失败不进入检索索引。
- [x] BM25：中英文及产品编号分词、词频/文档长度评分、按语言/SKU/资料可见范围过滤。
- [x] Hybrid RAG：独立向量适配器、向量版本与维度校验、BM25 + 向量候选的 RRF 融合；显式 bm25/hybrid 模式，缺向量服务时 hybrid 明确报错。
- [x] 资料生成邮件：按询盘检索经审核、允许对客使用的资料，验证引用、保存待人工审核草稿；不改变收件人、不自动确认或发送。
- [x] 3D 接入：受控后台调用接口、资料辅助设计提示、现有图片与 GPU 网关适配；缺配置/超时/失败明确报错，不自动放开匿名付费生成。
- [x] 安全：管理员会话和 CSRF、上传解析边界、资料默认私有/草稿、归档不再可检索、模型输出不执行、密钥仅服务端。
- [x] 交接：接口和环境变量说明、检索策略、失败路径及本地端到端测试；实际模型质量、送达、GPU 性能不冒充已验证。

2026-09-09 验收：219 项 TypeScript 测试、18 项 Python 测试通过，类型检查与本轮相关文件 lint 通过。生产导出 251 页；桌面 1440/手机 390 邮件 UI 验证通过。详情见 knowledge-mail-studio-verification-2026-09-09.md；接口手册见 knowledge-mail-studio-api.md。

## 实现边界

复用现有 Node/SQLite CMS 和 SMTP，不新建第二套后台。只新增资料与生成接口及调用适配，不重做官网视觉。客户资料没有录入前，知识检索应为空，RAG 应返回“无可用证据”，不能使用测试资料或泛化常识假装客户知识库已接通。

资料默认 `draft/internal`；只有管理员显式将可对客资料设为 `active/customer` 才能用于对客邮件和 3D 提示。原始资料与引用是非可信数据，不能修改系统提示、权限、收件人或触发工具。生成内容始终由人工核实，引用存在不等于结论正确。

默认实现单实例本地 SQLite 检索，适合首批资料；保留 embedding provider 接口和模型标识，不预装外部向量数据库。大规模资料再依据真实数量迁移索引，不宣称当前是分布式搜索系统。
