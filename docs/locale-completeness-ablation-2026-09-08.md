### 1. 阿拉伯文产品资料缺翻译，优先处理

- **238 处字段，154 条不同英文文本**：产品目录 78 处，技术膜型资料 160 处。154 按原文大小写区分；忽略大小写合并为 149 条。
- 21 个产品中，8 个产品名仍为英文，全部 21 个产品的品类／重量标签仍为英文。
- `Specialty patches` 同时出现在品类导航、面包屑、页标题和产品相关入口。
- 41 个膜型的名称、功效、包装资料，以及 5 个材料体系的名称与描述均通过英文默认值填充。
- 因此“有 ar 键”和“页面返回 200”不能证明该内容已翻译。

根因：`src/data/catalog.ts:205` 的字典缺项会返回英文；`src/data/hydrogel-formats.ts:30` 使用 `ar = en`，而多数内容只传入了中英文参数。

证据：[分类页面截图](../output/locale-audit-2026-09-08/ar-category-untranslated.png)、[字段明细](../output/locale-audit-2026-09-08/data-audit.json)、[全部页面正文与标题](../output/locale-audit-2026-09-08/rendered-audit.json)。

### 2. 中文文章切换语言进入 404

在 `/zh/insights/hydrogel-eye-mask-selection-guide/` 点击顶部语言菜单并选择 العربية，会进入 `/ar/insights/hydrogel-eye-mask-selection-guide/`，显示英文 `404 / This page could not be found.`。英文目标地址同样未提供文章。

根因：`src/lib/published-content.ts:39` 仅为中文返回文章；`src/components/header.tsx` 的语言切换统一保留当前路径，没有检查目标语言是否提供该文章。单纯不提供英阿文章可以是发布范围选择，但不能让切换入口指向不存在的文章。

建议：明确文章翻译范围。目标语言没有译文时，切换至该语言的文章列表，并给出对应语言的说明；若要求三语内容完全对等，再补齐两篇文章的英阿版本。

证据：[切换前](../output/locale-audit-2026-09-08/zh-article-before-switch.png)、[切换后](../output/locale-audit-2026-09-08/article-switch-ar.png)、[结果数据](../output/locale-audit-2026-09-08/article-switch-ar.json)。首次开发服务器直接请求阿语缺失路由曾返回 500；通过实际菜单复测后稳定呈现 404。本报告将其归为缺失目标页面，不将开发阶段 500 推断为线上行为。

### 3. 表单错误路径未完成本地化

三个语言分别提交了只含空格的必填文本和有效格式的测试邮箱。浏览器原生 required 检查通过，业务层 trim 后拒绝，三种语言都产生 8 条校验错误，例如：

`name: Too small: expected string to have >=1 characters`

中文和阿语仅错误框标题本地化，正文仍是英文。`src/components/inquiry-form.tsx:104` 直接拼接校验库的路径与消息。应按字段和错误类型生成当地语言的可执行提示，而非展示内部字段名。

本次均在客户端校验阶段拒绝，未创建有效询盘或发送邮件。

证据：[中文错误](../output/locale-audit-2026-09-08/zh-validation.png)、[阿语错误](../output/locale-audit-2026-09-08/ar-validation.png)、[错误明细](../output/locale-audit-2026-09-08/form-validation.json)。

### 4. 页面正文以外仍有英文残留

- `src/app/globals.css:502` 用 CSS 伪元素写死 `QUOTE DETAILS`，中阿表单都能看到，消息字典检查和普通 DOM 文本抽取不会发现它。
- 关于页写死 `EVIDENCE`；工厂图形使用 `HYDROGEL PRODUCTION`。这类展示文字需要明确是否保留品牌用语。
- 站点首页链接的辅助标签固定为 `Guangtuo Bio home`。
- 阿语 `/studio/`、`/status/` 的页面标题和描述仍用英文；`/ui-lab/` 的主体和标题也未完整提供阿语。实验室页面未纳入主导航，且设置了 noindex，但已存在于可访问路由中。

证据：[阿语实验室](../output/locale-audit-2026-09-08/ar-ui-lab.png)、[正文／元数据／辅助标签记录](../output/locale-audit-2026-09-08/rendered-audit.json)。CSS 残留也可见于表单错误截图。

## 消融实验

每次仅移除一个机制，其余数据与入口保持一致。翻译实验通过 esbuild 在 `output/locale-audit-2026-09-08/variants/` 创建独立模块，不修改业务源文件。对照涉及的 6 个源文件保存 SHA-256，实验前后相同；中英文控制数据逐字段比较无变化。

| 实验 | 对照组 | 移除后的结果 | 结论 |
| --- | --- | --- | --- |
| 去掉阿文的英文兜底 | 被测 804 个字段中，阿文空值为 0 | 277 个字段变为空值：目录 99、膜型 160、包装 18；其中 238 是缺失的自然语言译文，其余 39 为单位、代号等共享值 | 兜底掩盖了翻译缺项；正式补译时须区分自然语言和共享技术值 |
| 去掉公司页阿文扩展字典 | 公司页显示阿文 | 251 处字段退回英文，空值仍为 0 | 扩展字典有效且必要；只检查非空仍无法发现整组译文被移除 |
| 去掉 CMS 首页覆盖／文章集合 | 中文存在首页覆盖与 2 篇文章；英阿均无该覆盖与文章 | 中文首页覆盖消失，文章数量降至 0；英阿无变化 | 当前 CMS 内容是中文专用，不是三语同步内容源 |
| 去掉 Arabic RTL | `dir=rtl`，桌面品牌横坐标 1172px | 改为 `ltr` 后品牌移至 8px，内容布局改为从左到右，正文字符串不变 | 翻译与文字方向是两项独立要求；RTL 必须保留 |

RTL 实验结束后已恢复，方向和品牌位置重新与对照一致。CMS 实验只对函数传入副本，不更改已发布 JSON；该项结论是内容选择函数的行为，不是一次重新发布或完整页面重建。

证据：[翻译消融与源文件哈希](../output/locale-audit-2026-09-08/ablation.json)、[CMS 对照](../output/locale-audit-2026-09-08/data-audit.json)、[RTL 数值](../output/locale-audit-2026-09-08/rtl-ablation.json)、[RTL 对照截图](../output/locale-audit-2026-09-08/ar-products-desktop.png)、[移除 RTL 截图](../output/locale-audit-2026-09-08/ar-products-without-rtl.png)。

这些是功能依赖实验，没有流量、转化率或用户偏好数据，不能据此推断某个页面设计提高了商业效果。

- `pnpm test`：26 个测试文件、160 项测试通过。

- 交互与布局：三语 × 首页、产品中心、局部膜贴分类、询盘、文章列表、3D 工作室 × 1280×720 / 375×812，共 36 组；未发现整页横向溢出或已加载且处于视口内的损坏图片。个别横向滚动容器内部内容超出视口不计作整页溢出。

- 表单：验证客户端错误状态；没有提交有效询盘。3D 工作室只检查页面与本地配置内容，没有调用生成服务。

语言完整性未通过，但不等于整站不可用。现有 160 项自动测试全部通过的同时，上述可见缺失仍存在，后续应把缺翻译、缺失文章切换、错误文案和 CSS 文本纳入验收。

## 复跑

```powershell
pnpm dev --port 3100
pnpm exec tsx scripts/audit-locales.ts
pnpm exec tsx scripts/ablate-locales.ts
```

浏览器脚本复用已经安装的 gstack browse，设置 `BROWSE_BIN` 为其可执行文件路径；本机 Windows 安装还需设置 `BROWSE_SERVER_SCRIPT` 为配套 `dist/server-node.mjs` 的路径。

```powershell
node scripts/check-locale-browser.mjs http://localhost:3100 output/locale-audit-2026-09-08
```

用 browse 导航到本地站点后执行 `eval scripts/audit-rendered-locales.js`，在 `window.__localeAudit.completed === window.__localeAudit.total` 时，将 `JSON.stringify(window.__localeAudit)` 导出为 `rendered-audit.json`。默认输出目录为本次报告目录；复跑新批次时可给脚本传入新的输出目录。

后续处理顺序：补齐阿文产品资料；修复文章切换；本地化表单错误；清理元数据、辅助标签与 CSS 残留。完成后再使用同一批路由与控制条件验收。
